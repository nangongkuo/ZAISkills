# ACS Coding 交互文案库

## 使用说明

主调度器在对应场景下直接引用本文案的模板内容，保持交互一致性。

---

## 场景1：首次启动欢迎

**触发条件**：新任务，无状态文件

**输出文案**：

```
👋 欢迎使用 ACS Coding 工作流！

我将协助您完成移动端开发的完整流程：
📄 输入收集 → 📝 Spec流程 → 💻 编码编译 → 🧪 测试 → 🚀 提交PR

────────────────────────────────────────

请提供项目仓库路径：
→ 例如：/Users/username/project

或输入以下快捷命令：
. → 使用当前目录
? → 查看使用帮助
exit → 退出
```

---

## 场景2：路径验证成功

**触发条件**：用户输入路径，验证通过

**输出文案**：

```
📁 仓库路径：{repo_path}

✓ 路径存在
✓ Git仓库已初始化
✓ 当前分支：{branch_name}

状态检查：未找到未完成任务，开始新流程
────────────────────────────────────────

🚀 开始执行 [阶段{id}: {stage_name}]

执行模式：{execution_mode}
预计耗时：{estimated_time}

确认开始？ [Y/n]
```

**变量**：
- `{repo_path}` - 仓库绝对路径
- `{branch_name}` - 当前分支名
- `{id}` - 阶段编号
- `{stage_name}` - 阶段名称
- `{execution_mode}` - agent/inline
- `{estimated_time}` - 预估时间描述

---

## 场景3：路径不存在错误

**触发条件**：用户输入的路径不存在

**输出文案**：

```
⚠️ 路径不存在：{input_path}

请检查：
1. 路径拼写是否正确
2. 是否有访问权限
3. 是否需使用绝对路径

请重新输入仓库路径：
```

**变量**：
- `{input_path}` - 用户输入的原路径

---

## 场景4：非 Git 仓库错误

**触发条件**：路径存在，但非 Git 仓库

**输出文案**：

```
⚠️ 当前目录不是 Git 仓库

请检查：
1. 是否已进入正确的项目目录
2. 是否已执行 git init

或输入 `exit` 退出，进入仓库后再试。

请重新输入仓库路径：
```

---

## 场景5：断点恢复欢迎

**触发条件**：检测到未完成任务

**输出文案**：

```
👋 欢迎回来！检测到未完成的任务。

📍 当前阶段：阶段{current_id} ({current_name})
📁 仓库路径：{repo_path}
⏱️ 上次更新：{last_update_time}

执行概览：
{stage_status_list}

────────────────────────────────────────

请输入选项：
[1] 继续执行阶段{current_id}
[2] 查看详细状态
[3] 重置当前阶段
[4] 结束流程
```

**变量**：
- `{current_id}` - 当前阶段ID
- `{current_name}` - 当前阶段名称
- `{repo_path}` - 仓库路径
- `{last_update_time}` - 状态文件最后更新时间（格式化）
- `{stage_status_list}` - 各阶段状态列表，格式如下

**阶段状态项格式**：
```
✅ 阶段{id}: {stage_name} ({execution_mode}, {duration}s)
⏳ 阶段{id}: {stage_name} ({execution_mode}, {duration}s) - {status_note}
⏭️ 阶段{id}: {stage_name} - 跳过
○ 阶段{id}: {stage_name}
```

---

## 场景6：阶段完成确认

**触发条件**：阶段完成后需要用户确认继续

**输出文案**：

```
────────────────────────────────────────
✅ 阶段{id}: {stage_name} 完成

执行摘要：
执行模式：{execution_mode}
执行耗时：{duration}秒
{result_summary}

⚠️ 请确认是否继续下一阶段？
[Y] 是，继续执行
[N] 否，稍后再继续
[R] 查看详细结果
────────────────────────────────────────
```

**变量**：
- `{result_summary}` - 阶段执行结果摘要（多行）

---

## 场景7：使用帮助

**触发条件**：用户输入 `?`

**输出文案**：

```
📖 ACS Coding 使用帮助

命令列表：
<路径>       指定项目仓库路径
.            使用当前目录作为仓库路径
?            显示此帮助信息
exit         退出 ACS Coding

流程说明：
1. 输入收集    - 收集系分文档、设计稿，创建分支，准备知识
2. Spec流程    - 创建并确认变更提案 (OpenSpec)
3. 编码编译    - 实现代码并通过编译检查
4. 自动测试    - 打包安装验证（条件执行）
5. 提交PR      - 提交代码并创建 Pull Request

更多信息请参考：{skill_path}/SKILL.md
```

**变量**：
- `{skill_path}` - skill 文件所在目录

---

## 场景8：流程正常结束

**触发条件**：`is_final: true` 的阶段完成

**输出文案**：

```
🎉 ACS Coding 流程全部完成！

执行统计：
总阶段数：{total_stages}
跳过阶段：{skipped_count}
总耗时：{total_duration}秒
执行模式分布：agent({agent_count}), inline({inline_count})

────────────────────────────────────────
感谢您的使用，祝您开发愉快！
```

**变量**：
- `{total_stages}` - 完成的阶段总数
- `{skipped_count}` - 跳过的阶段数
- `{total_duration}` - 全流程耗时
- `{agent_count}` - agent 模式执行的阶段数
- `{inline_count}` - inline 模式执行的阶段数

## 文案使用规范

### 格式符号
- 分隔线：`────────────────────────────────────────`（40个半角横线）
- 状态标记：✅ 完成 | ⏳ 进行中 | ⏭️ 跳过 | ○ 待执行 | ⚠️ 警告
- 输入选项：`[X] 描述` 或 `[Y/n]`

### 变量替换
所有 `{variable}` 格式的文本必须在输出前替换为实际值。

### 换行规则
- 段落之间空一行
- 列表项缩进 2 个空格
- 分隔线前后各空一行
