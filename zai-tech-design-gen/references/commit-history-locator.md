# commit 历史定位通道 (commit-history-locator)

> 与 `prd-code-locator.md` 五层引擎**并行**的第六条定位通道。
> 五层引擎从"当前代码快照"找锚点；本通道从"git 历史变更记录"找"上次做类似需求改了哪些文件"。
> 主流程阶段 3 对**每个原子需求点**与五层引擎并行执行本协议。本文件可独立迭代优化。

## 定位（边界）

**触发通道**: 命中→提升置信、补充邻区块；落空**不改变**需求点判为未定位（仍由五层锚点层决定）。
对仓库**只读**，只跑 `git log/grep/show`，符合主流程 Workspace Rules，不追调用链（那是五层引擎的活），本通道只回答"改哪组文件"。

## 输入

单个原子需求点（同 `prd-code-locator.md` 的 schema; 本通道仅用 `做什么` / `技术领域关键词` / `UI文案` 做匹配, `功能场景` / `涉及字段` 不参与本通道）:
```
{
  id: "R1",
  做什么: "用户点击领取后展示优惠券弹窗",
  技术领域关键词: ["优惠券", "领取", "弹窗"],
  UI文案: ["立即领取"],
  涉及字段: ["couponId"]
}
```

## 输出

一个「历史参照」对象:
```
{
  需求点: "R1",
  历史命中: true | false,
  匹配commit: [                         // 最多 5 个, 新→旧
    { sha: "a1b2c3d", date: "2025-11-20", message: "feat: 新增优惠券领取弹窗" }
  ],
  高频改动文件: [                       // 按出现次数降序, 仅 test -f 通过
    { path: "src/coupon/CouponPopupManager.swift", 命中次数: 3, 状态: "现存" }
  ],
  历史路径线索: [                       // 已不存在, 仅线索不推荐
    { path: "src/old/LegacyCoupon.swift", 状态: "[历史路径, 现已不存在]" }
  ],
  置信度: 中 | 低
}
```

## 步骤 0 - 前置 & 取数（每次 skill 运行只做一次, 缓存给所有需求点共用）

```bash
# 0a. 是否 git 仓库 & 有无历史
git -C <repo> rev-parse --is-inside-work-tree
# 0b. 拉取窗口内 commit 的 sha + 日期 + message（默认最近 500 / 12 月, 取先到上限）
git -C <repo> log -n 500 --since="12 months ago" --no-merges --date=short \
  --pretty=format:'%h%x09%ad%x09%s'
```

只拉 message 清单（轻量）, 文件名按需在步骤 2 才拉, **不拉全量 diff**。
窗口 `N=500 / M=12月` 为协议内可调参数; 触上限则合并并在摘要提示"历史窗口已截断"。

**前置失败 → 整条通道跳过**（见降级表）:
- 0a 返回非 `true` / 报错（非 git 仓库）→ 跳过, 告知用户, 不阻主流程。
- 0b 输出为空（浅克隆 / 窗口内无 commit）→ 跳过。

## 步骤 1 - 关键词粗筛（缩小候选）

用需求点的 `技术领域关键词`（经 `prd-code-locator.md` 第④层**同款术语翻译**: 产品词+技术同义词矩阵, 如 优惠券>coupon/voucher/promotion/benefit、领取>fetch/receive/claim/draw、弹窗>dialog/popup/alert/sheet）+ `UI文案`，对步骤 0 缓存的 message 清单做**大小写不敏感**过滤，得到候选 commit（几条~几十条）。

```bash
# 复用步骤 0 缓存的 message 清单(下记为 $CACHED_LOG), 不重跑 git log; 示例:优惠券领取需求点
echo "$CACHED_LOG" | grep -i -E '优惠券|coupon|voucher|领取|claim|立即领取'
```

- 中文 message 直接匹配; 英文 message 用术语翻译后的英文词匹配。
- 命中 **0 条** → 该需求点历史参照为空（历史命中=false）, 结束本通道, **不阻塞**其他需求点。

## 步骤 2 - 语义筛选 + 抽改动文件集

1. 对候选 commit 的 message 做**语义判断**: "这个历史需求和当前需求点「做什么」是否同类？" 删除字面命中但语义无关的（keyword 撞库）。
2. 对剩余 commit（保留最多 5 个, 时间新→旧）抽改动文件:
```bash
git -C <repo> show --name-only --pretty=format: <sha>
```
3. 汇总所有文件路径, **按出现次数降序** + 看高频改动区域。
4. **强制验证**: 每个路径走 `test -f`。
   - 现存 → 标 "现存", 进「高频改动文件」。
   - 已被重构/删除 → 标 `[历史路径, 现已不存在]`, 进「历史路径线索」, **不进推荐, 仅作线索**。

**短路 & 边界: **
- 候选 >50 时只判断 15 条（新→旧）做语义判断, 摘要提示"已截断"。
- 不追调用链; 本通道只回答"改哪组文件"。

## 防幻觉 + 置信度规则（三条铁律）

1. **commit sha 必须真实**: 只能来自步骤 0 `git log` 真实输出, **禁止杜撰 sha**。阶段 6 对抗式自审会随机抽 1 个写入的 sha 跑 `git show <sha> --oneline` 验证存在（见 `adversarial-review.md`）。
2. **文件路径必须 `test -f`**: 同五层引擎规则, 不存在的归为「历史路径线索」, 不进推荐。
3. **历史参照无花板 = 中置信**（它是"组织证据", 非当前需求的直接锚点）:
   - 语义筛选命中且文件现存 → **中**
   - 仅粗筛命中未经语义确认, 或文件多已不存在 → **低**
   - **找不到"同类"**（需求回退给知识索引/UI文案直接锚定）。

## 与五层引擎的综合规则（阶段 5 生成时）

- 五层已命中（高置信）+ 历史参照同向 → 历史参照作**佐证**，增强说服力。
- 五层落空（未定位）+ 历史参照命中 → 该需求点从"未定位"提升为**「中置信·历史参照」**，给出参照区域让编码有起点，**但仍标注 `[基于历史推断，非当前代码直接锚定]`**。
- 两者冲突（五层指向 A 区, 历史指向 B 区）→ 阶段 6 自审打 `[需对齐]`，两者都列，交人审。

## 降级行为

| 情况 | 行为 |
|------|------|
| 非 git 仓库 / `rev-parse` 失败 | 跳过整条通道, 告知用户, 不阻塞主流程 |
| 浅克隆 / 窗口内无 commit | 跳过整条通道 |
| 某需求点粗筛 0 命中 | 该需求点历史参照为空, 不阻塞其他需求点 |
| 候选/文件过多 | 按上文截断规则并提示 |
| 历史路径全部已不存在 | 历史命中=true, 但置信度=低, 仅作线索 |
