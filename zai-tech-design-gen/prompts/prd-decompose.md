# PRD → 原子需求点 拆解提示 (prd-decompose)

> 主流程阶段 2 使用。把 PRD 正文拆成原子需求点清单, 作为后续所有分析的工作单元。

## 拆解原则

- **原子性**: 一个需求点 = 一个可独立实现/验证的功能行为, 不可再拆成两个独立动作。
- **可定位性**: 每个需求点要尽量抽出可用于代码检索的信号(UI 文案、字段、场景)。
- **不遗漏**: PRD 里的每个功能描述都要落到某个需求点, 不遗漏。
- **去产品话术**: 只保留“做什么”, 剥离营销/背景描述。
- **利用图片 OCR 文本**: 若 PRD 的设计截图片段以 HTML 注释形式内嵌 OCR 文本(形如 `<!-- 这是一张图片, OCR 内容为: ... -->`), 这些 OCR 文本里**往往含真实 UI 文案**(按钮字、提示词), 是 `UI文案` 字段最重要的来源, 必须合并提取。

## 输出 Schema

对每个需求点输出:
```
{
  id: "R{n}",
  做什么: "<一句话功能行为, 主谓宾完整>",
  功能场景: ["<页面/入口 1>", ...],
  技术领域关键词: ["<产品名词/动作, 用于术语翻译>", ...],
  UI文案: ["<PRD 中出现的按钮/提示原文>", ...],     // 没有则空数组
  涉及字段: ["<PRD 提到的数据字段>", ...]           // 没有则空数组
}
```

## 示例

PRD 片段:
> "用户在首页点击「立即领取」按钮后, 弹出优惠券领取弹窗, 展示券面额(amount)和有效期。已抢光时按钮变灰显示「已抢光」。"

拆解结果:
```
[
  {
    id: "R1",
    做什么: "用户点击领取按钮后弹出优惠券领取弹窗, 展示券面额和有效期",
    功能场景: ["首页"],
    技术领域关键词: ["优惠券", "领取", "弹窗"],
    UI文案: ["立即领取"],
    涉及字段: ["amount", "有效期"]
  },
  {
    id: "R2",
    做什么: "优惠券已抢光时领取按钮置灰并显示已抢光文案",
    功能场景: ["首页"],
    技术领域关键词: ["优惠券", "库存", "按钮状态"],
    UI文案: ["已抢光"],
    涉及字段: []
  }
]
```

## 质量自检

拆解完成后确认:
- [ ] PRD 中每个功能描述都有对应需求点
- [ ] 每个需求点的"做什么"是单一行为, 未塞入多个动作
- [ ] UI 文案字段尽量抽全(这是定位命中率最高的锚点)
