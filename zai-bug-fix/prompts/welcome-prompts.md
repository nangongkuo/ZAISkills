# Bug Fix 交互文案

## 场景1：欢迎文案

```
🔧 Bug Fix - 缺陷修复工作流

本工作流将帮助你分析并修复缺陷：
  1. 接收缺陷描述
  2. 分析根因（代码搜索 + commit 分析 + 用户确认）
  3. 生成修复方案（用户确认）
  4. 编码修复
  5. 提交代码

请输入：
  1. 仓库路径
  2. 缺陷描述
  3. 分支名称
  4. 日志文件/文件夹路径（可选）
  5. 触发时间（可选）

或输入 skip 跳过某项，? 查看帮助，exit 退出
```

## 场景3：缺陷描述询问

> **触发**：仅当 `defect_description` 已通过 args 传入，或场景 2.5 触发了「双源无结果」/「用户选择手动粘贴」/「双源失败」降级时使用。

```
步骤 2/5：缺陷描述

请描述要修复的缺陷:
  • 直接粘贴缺陷描述
  • 包含：现象、复现步骤、预期行为

→ 输入:
```

**成功:**
```
✅ 缺陷描述已记录

关键词：{defect_keywords}

确认继续？ [Y/n]
```

## 场景 2.5：缺陷查询与选择（强制执行）

> **触发**：默认场景。Stage 1 启动后，若调用方未通过 args 显式传入 `defect_description` 或 `defect_id`+`defect_source`，必须执行缺陷查询步骤（即使 `checking-skip=true` 也强制执行）。
> **目的**：自动从「伙伴」/「Dima」两个平台查询当前用户名下的活跃缺陷，让用户从合并列表中选择，自动转储为 `defect_description`。
> **数据源脚本**：`<skill_root>/scripts/huoban-mydefects` + `<skill_root>/scripts/query-dima-bugs.sh`

### 状态1：查询中

```
🔍 查询您名下的缺陷...

伙伴平台：查询中...
Dima 平台：查询中...

(首次启动 huoban-cli / dima 可能需要 5-15 秒)
```

### 状态2：列表展示

```
📋 我的缺陷（共 {N} 条）

伙伴（主集成版本前后）:
[1] {id} [{优先级}/{严重程度}] {标题} ({状态})
[2] {id} [{优先级}/{严重程度}] {标题} ({状态})
...

Dima（待开始/进行中）:
[{N+1}] {id} [{优先级}] {标题} ({状态})
[{N+2}] {id} [{优先级}] {标题} ({状态})
...

→ 输入编号选择缺陷，输入 m 手动粘贴，或直接粘贴缺陷描述:
```

> 列表完整输出（不裁剪），由调度器在收到用户下一条消息后按 `stages/acs-bug-fix-defect-input.md` 的 C-4 解析规则路由。

**用户选择编号后:**

```
✅ 已选：{id} {标题}
正在拉取缺陷详情...
```

**详情拉取成功:**

```
📋 缺陷描述：{标题} | {优先级}/{严重程度} | {id}
🔗 来源：    {huoban / dima}
🔗 链接：    {defect_url 或 "未知"}
```

### 状态3：双源无结果 / 用户主动选「手动粘贴」

```
⚠️ 未在伙伴 / Dima 找到您名下的活跃缺陷（或您选择手动粘贴）。

请直接粘贴缺陷描述（建议包含：现象、复现步骤、预期行为）：

→ 输入:
```

> 用户粘贴后，按场景 3 的「成功」分支提示关键词与确认。

### 状态5：输入无效

```
⚠️ 未识别的输入（{用户原文 前30字}）。

请重新输入：编号、`m`，或直接粘贴缺陷描述:
→
```

> 仅在用户输入为纯异常号 / 单字符无意义串（如 `y` / `n`）时使用；多行/长文本应按 C-4 规则视为直接粘贴的缺陷描述，不走此状态。

### 状态4：单源失败警告

```
⚠️ {huoban / Dima} 查询失败：{错误简述,如 "huoban-cli 未安装" / "网络错误" / "未登录"}
将仅展示另一源的查询结果。
```

> 失败原因尽量简短，不影响后续展示另一源结果或降级到状态3。两源都失败 → 直接进入状态3。

### 详情拉取失败

```
⚠️ 缺陷详情拉取失败：{错误}
将降级到手动粘贴。
```

> 出现详情拉取失败 → 直接进入状态3 让用户粘贴。

## 场景3.5：日志路径询问（可选）

```
步骤 3/5：日志路径（可选）

请提供本地日志文件或文件夹路径，用于阶段 2 根因分析时的堆栈/错误线索:
  • 文件： /Users/xxx/Downloads/crash.log
  • 文件夹： /Users/xxx/Downloads/logs/

无日志请直接回车跳过 / 输入 skip

→ 输入:
```

**成功:**
```
✅ 日志路径：{log_path}
```

**路径无效:**
```
⚠️ 日志路径无效：{error}（不阻塞流程，阶段 2 将跳过日志分析）
```

**跳过:**
```
○ 跳过日志路径
```

## 场景3.6：触发时间询问（可选，但建议提供）

```
步骤 4/5：触发时间（可选）

bug 触发的具体时间或时间段（任意格式），用于在大日志中精确定位关键时段。
本字段仅用于过滤日志，不影响 commit 分析。

示例:
  时间点:
    • 2026-05-19 14:30:25        ← 推荐，精度最高（默认 ±10 分钟窗口）
    • 2026-05-19 14:30           ← 推荐（默认 ±15 分钟）
    • 2026-05-19                 ← 当天裁剪
    • 14:30                      ← 假定为今天
  时间段（直接用作窗口）:
    • 2026-05-19 14:30 ~ 15:00
    • 14:30-15:00                ← 假定为今天
    • 14:30 到 15:00             ← 中文分隔符也可
  无法解析（自动降级为整体读取）:
    • 昨晚 / 上周三

时间不准确没关系，系统会自动扩窗 + 错误密度引导，定位实际错误聚集段。
直接回车 / skip 跳过。

→ 输入:
```

**成功:**
```
✅ 触发时间：{trigger_time}
```

**跳过:**
```
○ 跳过触发时间
```

## 快捷命令

| 命令 | 作用 |
|------|------|
| skip | 跳过当前输入 |
| auto | 自动生成分支名 |
| ? | 查看帮助 |
| Y/n | 是/否 |
| exit | 退出 |
